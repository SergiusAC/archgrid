# ADR-0005. Совместная работа: presence сейчас, CRDT только для layout потом

- **Статус:** accepted
- **Дата:** 2026-08-17

## Контекст

Исходная идея предполагала WebSocket + Yjs/CRDT для совместного редактирования. Бэкенд — Spring Boot, разработчик один.

## Решение

- **MVP:** presence по WebSocket (курсоры, выделение соавторов) + оптимистичная блокировка по версии. Конфликт версий возвращает 409 с диффом расхождения.
- **Фаза 9:** CRDT **только для layout-слоя** — координаты, waypoints, стили. Семантическая модель остаётся транзакционной: команды, серверная валидация, коммиты.

## Обоснование

**Архитектурное (основное).** CRDT — неподходящий инструмент для семантической модели. Смысл CRDT: «конфликтов не бывает, любые правки сливаются». Смысл типизированной архитектурной модели: «недопустимые состояния невозможны». Два корректных CRDT-мержа способны дать граф, нарушающий метамодель, и обнаружить это некому — в CRDT-схеме сервер лишь ретранслирует операции.

Архитектурное изменение — это решение, которое проходит review. Модель должна вести себя как Git, а не как Google Docs. Layout при этом ведёт себя именно как Google Docs, и там CRDT уместен. Разделение слоёв (ADR-0003) делает такую раздельную стратегию возможной.

**Техническое.** Yjs — JS-библиотека. При Spring Boot это либо Node-сайдкар `y-websocket` (третий рантайм в on-prem-поставке), либо незрелые JVM-биндинги `y-crdt`. Для одного разработчика — отдельный проект, а не фича.

**Продуктовое.** Presence даёт большую часть ощущения совместной работы за малую долю стоимости. Реальная одновременная правка одной диаграммы двумя архитекторами — редкий сценарий по сравнению с редактированием документа.

## Последствия

- В MVP два человека, правящих одно представление, получат конфликт версий. Смягчается presence: видно, что кто-то работает рядом.
- Требуется качественный UI разрешения конфликта: показать дифф, предложить rebase команд.
- Если позже решим внедрять CRDT для layout, третий рантайм в поставке всё ещё под вопросом — рассмотреть JVM-реализацию или собственный OT для ограниченного типа операций.
