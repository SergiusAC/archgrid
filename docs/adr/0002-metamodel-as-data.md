# ADR-0002. Метамодель ArchiMate реализуется как данные, а не как код

- **Статус:** accepted
- **Дата:** 2026-08-17

## Контекст

Принято решение о совместимости с ArchiMate 3.2 с самого начала. Это ~60 типов элементов, ~11 типов связей и матрица разрешённых связей порядка 60×60, плюс правила деривации. Реализует один разработчик.

## Решение

Метамодель описывается в версионируемом машиночитаемом файле `metamodel/archimate-3.2.yaml`: типы элементов, типы связей, порядок силы связей, матрица разрешённых сочетаний, viewpoint'ы и их палитры, сопоставление с нотацией C4. Файл загружается в БД при старте с проверкой контрольной суммы. Код содержит интерпретатор метамодели, а не саму метамодель.

## Обоснование

- Матрица из тысяч сочетаний, выраженная условными операторами, нетестируема и неподдерживаема.
- Данные можно валидировать автоматически: полнота, отсутствие противоречий, разрешимость ссылок.
- Расширение метамодели (новые viewpoint'ы, сопоставления с другими нотациями) становится правкой файла, а не релизом.
- Файл — естественная точка сверки со спецификацией при аудите.

## Обязательное требование

Матрица разрешённых связей и порядок силы структурных связей **транскрибируются из официальной спецификации ArchiMate 3.2 (Приложение B)**. Не по памяти, не из вывода LLM, не из стороннего репозитория без построчной сверки. Ошибка здесь означает, что продукт даёт архитектору ложную гарантию корректности — единственная ошибка, которую целевой пользователь не прощает.

## Источник и его статус (обновлено 2026-08-17)

Основа — `relationships.xml`, `relationships-keys.xml` и `viewpoints.xml` из [Archi](https://github.com/archimatetool/archi) (MIT, файл объявляет `version="3.2"`). Проведена сверка с XSD формата обмена The Open Group; полный протокол — [`metamodel/VERIFICATION.md`](../../metamodel/VERIFICATION.md).

| Часть метамодели | Статус |
|---|---|
| Типы связей (11) | **Сверено с первоисточником**, расхождений нет |
| Типы элементов (60 + 2 служебных) | **Сверено с первоисточником**, оба расхождения объяснены кодированием |
| Матрица разрешённых связей | **Не сверена.** XSD её не описывает — только Приложение B спецификации |
| Порядок силы структурных связей | **Не сверена** |
| Палитры viewpoint'ов | **Не сверены** |

Пока строки 3–5 не закрыты, продукт не вправе заявлять соответствие метамодели. Закрытие требует текста спецификации ArchiMate 3.2 и остаётся в списке фазы 1.

Установлено на данных: матрица Archi существенно включает выводимые (derived) связи — замкнутость по структурному правилу «слабейшего звена» составляет 97 % на 58 основных концептах. Следовательно, она отвечает на вопрос «допустима ли связь между этими типами вообще», но не различает явную и выводимую связь; это различение вычисляет наш движок деривации по фактическому графу, как и предполагает `docs/02-architecture.md` §6.

## Последствия

- Фаза 1 плана целиком посвящена этой работе, включая ~5 дней на транскрипцию и сверку.
- UI показывает не полный набор типов, а палитру текущего viewpoint'а (10–15 элементов). Полнота модели не равна полноте палитры.
- Кастомная метамодель на тенанта в v1 не поддерживается: она взаимоисключающа с гарантией соответствия ArchiMate.

## Юридическое решение (принято 2026-08-17)

Риск принят владельцем продукта осознанно. Зафиксированы два разных вопроса и принятые по ним решения:

1. **Производность матрицы.** Код Archi лицензирован под MIT, но содержание матрицы производно от спецификации The Open Group, и MIT авторских прав на неё не отменяет. Решение: использовать, риск принять, юридическую проверку не считать блокирующей для разработки. Атрибуция Archi обязательна в NOTICE поставки.

2. **Торговая марка.** «ArchiMate» — торговая марка The Open Group. Обязательные формулировки:

   - **Допустимо:** «ArchiMate 3.2 compatible metamodel», «supports the ArchiMate modelling language».
   - **Недопустимо без сертификации The Open Group:** «ArchiMate-certified», «certified ArchiMate tool», «conforming implementation» и любые производные, подразумевающие пройденную сертификацию.

   Ограничение распространяется на UI, документацию, README, сайт и коммерческие материалы, а не только на маркетинг.

Это инженерная фиксация принятого решения, а не правовое заключение.
