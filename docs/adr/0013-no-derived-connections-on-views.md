# ADR-0013. Представление рисует только то, что модель утверждает

- **Статус:** accepted; решение владельца продукта, принято вопреки рекомендации автора реализации
- **Дата:** 2026-08-20
- **Изменяет:** практику из фазы 4 ([ADR-0009](0009-views-and-folders.md), [03-roadmap.md](../03-roadmap.md) §Фаза 4)
- **Затрагивает:** [ADR-0007](0007-c4-projection.md)

## Контекст

С фазы 4 представление получало два списка линий: **явные** связи (обе конца на виде) и
**выводимые** — те, что модель подразумевает через элементы, которых на виде нет. Выводимые
рисовались бледнее, с пометкой `(derived)`, и несли путь вывода, чтобы диаграмма умела ответить
«почему здесь эта линия».

Владелец продукта решил: на представлении должен быть **один тип линии**.

## Решение

Представление рисует только связи, которые модель **утверждает**. Выводимые связи на виде не
показываются: сервер их не считает для этого запроса, клиент не знает про них ничего, отдельного
оформления у линии больше нет.

Движок `RelationshipDerivation` **остаётся** — он не мёртвый код: на нём стоит проекция C4, где
сосед свёрнут до содержащей его системы и линию взять больше неоткуда, и он же понадобится анализу
влияния в фазах 6–7.

## Возражения, которые были высказаны и отклонены

Записаны не для спора, а чтобы через полгода никто не открывал этот вопрос заново, не зная, что его
уже закрывали.

1. **Стирается граница между тем, что модель утверждает, и тем, что из неё следует.** Явная линия —
   зафиксированное решение; выводимая — цепочка через три прыжка. Продукт стоит на том, что граф
   является источником правды, и различие было частью этого обещания.
2. **Пропадает ответ «почему здесь эта линия»** — путь вывода (`via`) больше некуда показать.
3. Возражение «слитая линия окажется неудаляемой» отклонено само собой: линий, которых нет в
   модели, на виде теперь просто нет. Это, наоборот, побочная выгода — правый щелчок работает на
   любой линии, потому что за каждой стоит настоящая связь.

## Что это стоит

**Контекстное представление системы, части которой общаются с внешним миром, не покажет ни одной
линии наружу.** Это ровно тот случай, ради которого контекстные диаграммы и рисуют: `Payment System`
содержит `Payment API`, тот обслуживает `Notification System`; на виде с двумя системами теперь
пусто между ними. Раньше там была выводимая Serving с путём через «Payment API».

Практический обход для архитектора: либо провести связь между системами явно (тогда она есть в
модели и рисуется), либо добавить на вид промежуточный элемент.

**Проекции C4 задеты этим сильнее всего.** Сам ответ `GET /projections/c4` по-прежнему содержит
выводимые связи, но проекция материализуется в обычное представление ([ADR-0007](0007-c4-projection.md)),
а обычное представление их не рисует. То есть C4-контекст показывает боксы и молчит о связях между
ними, пока архитектор не проведёт их явно.

## Как вернуть

Возврат — это одно изменение в четырёх местах; движок, правила и его тесты никуда не девались.

1. **Сервер.** В `GraphController.view(...)` вернуть в ответ список
   `RelationshipDerivation.derive(graph, shown, metamodel)`, отображённый в
   `ModelApiDtos.DerivedRelationshipResponse` (запись цела — её использует ответ проекции C4), и
   вернуть поле `derived` в `ModelApiDtos.ViewResponse`.
2. **Клиент.** Вернуть `derived: DerivedRelationship[]` в `ViewDetail` (`web/src/api/types.ts`),
   в `Editor.tsx` — второй список в `canvasLinks` с пометкой `(derived)`, в `Canvas.tsx` — флаг
   `derived` у `CanvasLink`, пунктир `'3 5'` и класс `ag-link-derived`.
3. **Стили.** Вернуть в `web/src/index.css` правило `.ag-link-derived { opacity: 0.6 }` и курсив
   для его подписи.
4. **Проверки.** В `.claude/skills/run-archgrid/driver.mjs` заменить проверку «taking a nested
   element off the view leaves no implied line behind» на прежнюю — «a dependency of a nested
   element lifts to its container», — и, если понадобится, вернуть блок про изломы выводимой линии.

Самый быстрый путь — `git revert` коммита с этим ADR: он снял ровно это и ничего больше.

Одно предостережение при возврате: маршруты линий (`view_layout_link`) ключуются **линией**, а не
связью — именно затем, чтобы выводимая линия могла хранить свои изломы (миграция V13). Это менять
не нужно ни при каком исходе: ключ по линии верен и без выводимых связей.
