# ADR-0015. Импорт принимает всё допустимое и отбрасывает недопустимое поимённо

- **Статус:** accepted; доменный механизм — `ModelChange.applyForImport`, сделано
- **Дата:** 2026-08-22
- **Связано с:** [ADR-0004](0004-commands-and-versioning-from-day-one.md),
  [ADR-0012](0012-archimate-exchange-format.md), [ADR-0011](0011-nesting-is-presentation.md)

## Контекст

Конвейер команд валидирует **весь граф-кандидат** и отвергает батч целиком: одно недопустимое
утверждение — и ничего не применяется (ADR-0004). Для редактора это правильно — пользователь
исправляет и повторяет. Для импорта чужого файла это неприемлемо: импортированные модели почти
всегда содержат то, что чей-то редактор пропустил, и вопрос «что делать с файлом, нарушающим
метамодель» надо было решить **до** импортёра, а не внутри него.

Вопрос впервые упёрся в нас на миграции V10: в реальных данных нашлась вложенность
`ApplicationComponent → ApplicationService`, которую ArchiMate запрещает, и превращение её в строку
Composition оставило бы репозиторий, отвергающий любую следующую команду.

## Варианты

1. **Отвергнуть файл целиком с отчётом.** Честно, но делает импорт бесполезным: почти каждый чужой
   файл нарушает что-нибудь, и продукт, который отвечает «исправьте модель в Archi и приходите
   снова», миграцию не открывает, а закрывает.
2. **Импортировать допустимое, отбросить недопустимое, назвать каждое отброшенное.** Потеря
   данных, но именованная, и модель после импорта валидна — репозиторий продолжает держать своё
   главное обещание.
3. **Принять всё, пометив недопустимое карантином.** Ничего не теряется, но «карантин» — это
   третье состояние связи, которое должны понимать валидация, деривация, представления, экспорт и
   каждый будущий потребитель графа. Цена размазана по всей системе навсегда, ради строк, которые
   язык всё равно запрещает утверждать.

## Решение

**Вариант 2.** Прецедент уже в кодовой базе: ровно так поступила миграция V10, и её рассуждение
переезжает сюда дословно — записать недопустимое как факт значит получить репозиторий, который
отвергает любую следующую команду; отбросить молча значит врать; отбросить **поимённо** — единственный
исход, после которого и модель валидна, и пользователь знает цену.

Три правила:

- **Отчёт — часть результата, а не лог.** Импортёр обязан вернуть список отброшенного тем же типом
  `Violation`, которым конвейер объясняет отказы: код, виновник, объяснение словами (ADR-0004 —
  «валидация должна объяснять» — распространяется и на импорт).
- **Толерантен только импорт.** `POST /commands` остаётся строгим; толерантный режим — отдельный
  вход в домене, `ModelChange.applyForImport`, и ничего в обычном конвейере его не зовёт.
- **После импорта граф валиден без оговорок** — `applyForImport` гарантирует это конструкцией, а
  не обещанием (см. ниже).

## Механизм

`applyForImport` применяет команды как обычный `apply` — команды, которые не могут примениться
(неизвестный тип, дубль ключа, висячий конец), уже пропускаются с записью нарушения. Затем, вместо
отказа, нарушения валидации всего графа **вырезаются из кандидата**:

- связь, которую матрица не разрешает, — удаляется;
- связь с висячим концом — удаляется;
- цикл композиции — разрывается удалением одной входящей Composition виновника;
- член представления, которого нет в модели, — снимается с представления.

Удаление строк не порождает новых нарушений — валидация проверяет существующее, не отсутствующее, —
поэтому цикл «валидировать → вырезать» сходится; финальная валидация обязана быть пустой, и
непустая — это ошибка программиста, а не данных (исключение, не отчёт).

## Последствия

- Импортёр OEF (фаза 6) строится поверх: разбор файла → команды → `applyForImport` → отчёт
  «отброшено» плюс отчёт «интерпретировано» (дубли, стили — ADR-0012) одним документом.
- Повторный импорт того же файла идемпотентен по этому пути ровно настолько, насколько
  идемпотентны команды; reconciliation фазы 6c — отдельная задача, это решение её не предрешает.
- Пользователь, которому нужен вариант 1 («не трогайте базу, если файл грязный»), получает его
  бесплатно: отчёт известен до коммита, и импортёр может предложить отмену, пока транзакция не
  закрыта.
