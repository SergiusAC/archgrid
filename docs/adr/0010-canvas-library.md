# ADR-0010. Канвас на JointJS core; React Flow заменяется

- **Статус:** предложено
- **Дата:** 2026-08-17
- **Пересматривает:** выбор React Flow из [01-tech-stack-review.md §5](../01-tech-stack-review.md)
- **Опирается на:** [ADR-0003](0003-model-view-layout-separation.md)

## Контекст

React Flow был принят на фазе 0 с тремя оговорками — производительность, авто-layout, «не клади семантику в `node.data`». Все три оказались верны и все три соблюдены. Ошибка была в другом, и оговорки её не покрывали: **React Flow — редактор потоков, а не редактор диаграмм.**

Симптом накапливался. Каждая итерация по замечаниям к UI сводилась к реализации вручную того, что редактор диаграмм даёт из коробки: изменение размера, вложенность, точки связи по сторонам, неперекрытие при размещении. Ни одна из этих правок не была специфична для ArchiMate — все они общее место любого редактора схем.

Требование, которое сделало решение однозначным, сформулировано так: линии прямые по умолчанию; горизонтальные или вертикальные, если расположение элементов позволяет; иначе прямые диагональные; **на пересечениях — небольшой перескок одной линии над другой, как в схемотехнике**.

Первая часть требования — это не ортогональный роутер. Прямая между двумя элементами, выровненными по оси, горизонтальна или вертикальна сама собой. Нужен прямой коннектор плюс перескоки — то есть ровно то, чего у React Flow нет и что пришлось бы писать с нуля вместе с обнаружением пересечений.

Есть и второе, отложенное следствие. Узлы React Flow — это HTML-`div`. Фаза 5 генерирует arc42, где диаграммы нужны векторными; из HTML-канваса получается только растр. Это не косметика, а заложенный тупик.

## Спайк

Одна и та же сцена собрана на обеих библиотеках: контейнер с вложенным элементом, пара, выровненная по горизонтали, пара, выровненная по вертикали, две диагонали, пересекающиеся посередине, овал сервиса, метки на связях. Код — `spike/canvas/`, снимки — `build/ui-check/spike-*.png`.

## Решение

**JointJS core (`@joint/core`).**

Решает не сумма галочек — она почти равная, — а **стоимость недостающего у каждого**.

- Чего нет у JointJS: направляющие выравнивания. Написаны в спайке за **60 строк** и работают точно: перетаскиваемый элемент прилип край в край (100 против 100), направляющие рисуются на обеих осях. Это сравнение шести линий каждого элемента с шестью линиями остальных — задача без подвохов.
- Чего нет у maxGraph: перескоки на пересечениях. Это обнаружение пересечений каждой линии со всеми остальными, разрезание пути и пересчёт при каждом движении любого элемента. Именно это draw.io построил **поверх** mxGraph, а не взял из него.

Меньшая по объёму дыра закрывается за полдня, большая — это отдельная подсистема. Плюс maxGraph до 1.0: для одного разработчика ломающиеся мажорные версии — реальная цена.

Отдельно: незрелость maxGraph — не приговор ему, а вопрос момента. Пересмотреть стоит, если он дойдёт до 1.0 и обзаведётся перескоками.

## Последствия

**Что не меняется — и это главная причина, почему замена вообще посильна.** Канвас намеренно тупой ([ADR-0003](0003-model-view-layout-separation.md)): семантика идёт командами, координаты — отдельным endpoint'ом, `node.data` не содержит модели. Сервер, команды, деривация, версионирование, layout API, метамодель, профили, проекции C4 — **не трогаются**. Заменяются `Editor.tsx`, `ArchimateNode.tsx`, `notation.ts` и разметка канваса.

Оговорка про React Flow из §5 обзора техстека («не клади семантику в `node.data`») оказалась ценнее, чем сам выбор библиотеки: именно она сделала библиотеку заменяемой.

**Что придётся написать самим:** направляющие (сделано в спайке), палитра и панель свойств (у нас свои, от канваса не зависят), стек undo (свой, работает).

**Лицензия.** MPL-2.0 — копилефт на уровне файла. Использование немодифицированной библиотеки в проприетарном продукте разрешено; если мы правим файлы самой JointJS, изменённые файлы подлежат публикации. Правок не планируется; при необходимости расширять — наследованием в своих файлах, а не патчами в чужих.

**Риск, принимаемый осознанно.** JointJS+ — коммерческая надстройка, и часть удобств редактора там. Мы уже сейчас пишем этот слой сами и на React Flow, так что положение не ухудшается; но если таких мест наберётся много, стоит сравнить стоимость лицензии с трудозатратами, а не продолжать по инерции.

**Проверка.** Режимы `driver.mjs smoke` (15 проверок) и `interactions` (13) написаны против поведения, а не против внутренностей React Flow — селекторы на `.ag-node`, `.ag-canvas`, `.ag-picker` и на геометрию. Часть селекторов придётся поправить, но сами проверки — это спецификация того, что редактор обязан уметь, и они переживают смену библиотеки.
