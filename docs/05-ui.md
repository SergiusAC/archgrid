# ArchGrid — интерфейс: что есть и что с ним не так

Описание текущего UI на конец фазы 3 и критический разбор. Вторая половина документа важнее первой: она список того, что переделать, с обоснованием.

---

## 1. Что есть сейчас

### Экраны

```
Вход через Keycloak
   ↓
Выбор репозитория (при единственном пропускается)
   ↓
Редактор — три колонки
```

### Редактор

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ ArchGrid   ArchiMate 3.2 compatible   acme  switch          architect  Выход │
├──────────────┬┬───────────────────────────────────────────┬┬─────────────────┤
│ Views │ Pal… ││ Payments context Draw[Serving▾] Auto-layout││ Свойства        │
│ │Repository  ││ Undo Redo  Remove from view  Delete from…  ││                 │
│              │├───────────────────────────────────────────┤│ Имя             │
│ + New view   ││  ┌─ Payment System ────────────┐           ││ Документация    │
│ + folder     ││  │  ┌────────────┐             │           ││ Атрибуты        │
│ ▾ Диаграммы  ││  │  │ Payment API│             │──Flow──▶  ││ профиля         │
│   Payments 3 ││  │  └────────────┘             │   [Kafka] ││ Свойства        │
│   Messaging 2││  └─────────────────────────────┘           ││ Где используется│

└──────────────┴┴───────────────────────────────────────────┴┴─────────────────┘
                ↑ разделители: тянутся, сворачиваются кнопкой ↑
```

**Левая колонка, три вкладки:**

| Вкладка | Содержимое |
|---|---|
| Views (N) | Дерево папок с представлениями, создание представления и папки |
| Palette | Выбор viewpoint, специализации, типы элементов по слоям |
| Repository (N) | Дерево папок со всеми элементами, поиск, «add» для добавления на представление |

**Канвас** рисует одно представление. Узлы окрашены по слою ArchiMate, специализация показана как `«Microservice»`. Связи несут нотацию: ромб у источника для композиции, полый треугольник для реализации, открытая стрелка для обслуживания, штрих с закрашенной стрелкой для потока.

**Правая колонка** — свойства выделенного элемента: имя, документация, атрибуты профиля отдельными полями по типу, произвольные свойства, список связей с переходом.

### Что работает

- **Magic Connector.** Единственный способ провести связь: кнопка `Connect`, щелчок по источнику, щелчок по цели. Тип выбирается после, когда метамодель уже знает оба конца: единственный допустимый рисуется без вопроса, несколько — предлагаются списком с клавиатурой. Бросок на пустое место создаёт элемент вместе со связью.
- **Два режима удаления.** «Remove from view» — элемент остаётся в репозитории. «Delete from repository» — с подтверждением, перечисляющим уходящие связи. Оба в правом щелчке и на `Delete`, а не на панели.
- **Undo/redo** по Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y, одним стеком: команды отменяются обратными командами и порождают коммит, перемещения — восстановлением координат.
- **Именование по месту** сразу после создания элемента.
- **Сохранение по требованию.** Правки раскладки живут черновиком в браузере и переживают перезагрузку; `Save` или Ctrl+S отправляет их на сервер, `Discard` возвращает сохранённое.
- **Нотация ArchiMate**: прямоугольник с иконкой типа в правом верхнем углу, цвет по слою, стереотип `«Microservice»`; ромб у источника композиции, полый треугольник реализации, открытая стрелка обслуживания, штрих с закрашенной стрелкой у потока.
- **Линии**: прямые по умолчанию, ортогональные — переключателем на представление; перескок дугой на пересечениях; якорь скользит по стороне, чтобы линия входила под прямым углом; изломы на прямом роутере.
- **Направляющие выравнивания** при перетаскивании — советуют, не притягивают. Сетка 10 едина для перемещения, размера и размещения.
- **Изменение размера** за восемь ручек, шагом по сетке.
- **Вложенность** перетаскиванием одного элемента в другой — приём представления ([ADR-0011](adr/0011-nesting-is-presentation.md)): контейнер не двигается и не уменьшается, редактор предлагает создать структурную связь, а выраженную вложенностью линию не рисует.
- **Палитра** переносом на канвас: элемент встаёт там, где отпустили; типы окрашены по слою.
- **Дерево** представлений и элементов с направляющими отступов, иконками, ходьбой стрелками.
- **Панель свойств**: имя и документация по кнопке `Save`, атрибуты профиля отдельными полями по типу, произвольные свойства, список связей с переходом и удалением.
- **Боковые панели** тянутся за разделитель и сворачиваются.

## 2. Критический разбор

### 2.1. ✅ Исправлено: Ctrl+Z не отменял перемещение

Undo работает по стеку команд, а координаты через команды не идут — это правильно архитектурно ([ADR-0003](adr/0003-model-view-layout-separation.md)) и **неправильно с точки зрения пользователя**. Он двигает прямоугольник, жмёт Ctrl+Z и получает отмену переименования, сделанного пять минут назад. Это не мелкое неудобство: пользователь перестаёт доверять undo вообще и перестаёт им пользоваться.

**Как чинить:** два независимых стека. Ctrl+Z отменяет последнее действие *в этом контексте*: если последним было перемещение — перемещение, если команда — команду. Стек layout живёт в браузере и не переживает перезагрузку, что нормально.

Это первое, что я бы сделал в следующем инкременте.

### 2.2. Вторая серьёзная: undo не знает про представления

Стек истории глобальный, а представления — независимые контексты. Отменив что-то, переключившись на другое представление и нажав Ctrl+Z ещё раз, пользователь изменит то представление, которого не видит. Изменение произойдёт молча.

**Как чинить:** либо стек на представление, либо, при отмене команды, относящейся к другому представлению, — переключиться на него и показать, что произошло. Второе честнее: история модели одна.

### 2.3. ✅ Исправлено: создание элемента давало ему имя типа

Нажав «Application Component», пользователь получает элемент с именем «Application Component» и должен пойти в правую панель переименовывать. На десяти элементах это десять переходов между колонками.

**Сделано:** после создания имя на канвасе сразу становится полем ввода с выделенным текстом. Enter применяет, Escape оставляет имя типа. Событиям мыши и клавиатуры поставлен stopPropagation, иначе React Flow начинал перетаскивание вместо ввода.

### 2.4. ✅ Исправлено: тип связи выбирался до рисования

Выпадающий список «Draw: Serving» нужно установить *перед* протягиванием. Пользователь думает «соединю эти два», а не «сейчас проведу Serving».

**Сделано:** если тип с панели допустим — связь создаётся сразу, без лишнего клика. Если нет — вместо ошибки открывается список того, что допустимо, с объяснением: «Realization is not permitted from Application Component to System Software. Permitted instead: Flow, Association, Triggering, Serving». Бросок разрешается всегда, когда между элементами возможно хоть что-то: отвергать жест, чтобы заставить пользователя сначала поменять выпадающий список, значит выбрасывать его работу.

**Доделано позже, тремя шагами меньше:**

- **Бросать можно в середину элемента**, а не в точку 10×10. Радиус захвата шире половины узла, так что цель жеста — элемент, а сторону редактор выбирает сам. До этого связь молча не возникала, если промахнуться мимо точки, — жест выглядел проигнорированным.
- **Единственный допустимый тип не спрашивают.** Выбор из списка в один пункт — действие без решения. Связь рисуется, в строке состояния сказано какая и почему; путь назад — undo.
- **Список типов управляется с клавиатуры.** Фокус уходит на первый пункт, Enter берёт его, стрелки двигают, Escape отменяет. Диалог прерывает жест мышью, но это не повод возвращаться к мыши второй раз.

### 2.5. Три вкладки смешивают навигацию и создание

Views и Repository — навигация, Palette — создание. Чтобы добавить элемент и потом найти другой, нужно переключить вкладку туда и обратно. Частота использования у них разная, а вес в интерфейсе одинаковый.

**Как чинить:** Palette — не вкладка, а всплывающая панель по кнопке или по двойному щелчку на пустом месте канваса. Слева остаются две вкладки: репозиторий и представления.

### 2.6. Нельзя завести элемент, не положив его на представление

Палитра создаёт элемент и сразу добавляет на открытое представление. Заполнить репозиторий (инвентаризовать системы), не рисуя диаграмму, нельзя. Для наполнения из реального ландшафта это основной сценарий.

**Как чинить:** создание элемента в репозитории отдельным действием во вкладке Repository. Импорт из фазы 6 всё равно будет создавать элементы без представлений.

### 2.7. Нет перетаскивания из репозитория на канвас

Добавление идёт по маленькой ссылке «add». Ожидается перетаскивание — оно и понятнее, и сразу задаёт позицию.

### 2.8. Папки переназначаются крошечным выпадающим списком

Он появляется по наведению и почти не заметен. Ожидается перетаскивание внутри дерева.

Дерево при этом переделано: одна плоская лента одинаковых строк вместо списка, вложенного в
список. Направляющие отступов, треугольники раскрытия, иконки папки и листа, подсветка строки
целиком, ходьба стрелками. Выпадающий список остался — он и есть остаток этого пункта.

### 2.9. «Где используется» не отвечает про представления

Панель свойств и контекстное меню показывают связи элемента, но не показывают, **на каких представлениях он есть**. Между тем перед удалением из репозитория это важнее списка связей: «удалится с 4 диаграмм» конкретнее, чем «удалится отовсюду». Данные на сервере есть (`ModelGraph.viewsShowing`), в API не выведены.

### 2.10. Представление нельзя переименовать или удалить из UI

Команды `rename-view` и `delete-view` реализованы и работают, кнопок нет. Создать представление можно, избавиться от него — нет.

### 2.11. Viewpoint спрятан в палитре

Смена viewpoint — свойство представления, а лежит во вкладке создания элементов. Место ей рядом с именем представления.

### 2.12. ✅ Исправлено: боковые панели были фиксированной ширины

Правая панель занимала 18rem, даже когда ничего не выделено, левая — 15rem всегда. Канвас — самая ценная область экрана, и панели забирали её независимо от того, есть ли им что показать.

**Сделано:** обе панели тянутся за разделитель и сворачиваются кнопкой на нём. Ширина живёт в браузере и на сервер не ходит — это оформление рабочего места, а не свойство модели.

Две ошибки по дороге, обе видны только в браузере:

- `.ag-sidebar` задаёт `display: flex`, и это перебивает атрибут `hidden` (у него `display: none` из таблицы браузера, приоритет ниже). Панель «сворачивалась» и оставалась на экране.
- Свёрнутая панель размонтируется, а в гриде оставалось пять колонок на четыре элемента — канвас и оба разделителя съезжали на колонку влево, и разделитель растягивался на весь экран. Колонок теперь ровно столько, сколько отрисовано.

### 2.13. Диалоги — это `window.prompt` и `window.confirm`

Создание представления и папки спрашивает имя системным `prompt`. Он не стилизуется, не валидирует и в некоторых браузерах блокируется. Для подтверждения удаления `confirm` ещё терпим, для ввода имени — нет.

### 2.14. ✅ Исправлено: сохранение было автоматическим и молчаливым

Layout уходил на сервер через 500 мс после перетаскивания, без единого признака, что это произошло. Пользователь не знал, сохранено ли, и закрывал вкладку неуверенно. Хуже того: это был источник **всех** гонок, на которые редактор натыкался — сохранение в полёте против перечитывания, отложенная запись, приходящая после изменения, которое она должна была зафиксировать, раскладка, записанная поверх настоящей.

**Сделано:** классическая схема. Правки живут черновиком в браузере и переживают перезагрузку и перезапуск браузера; на панели видно `Save *` или `Saved`; отправка на сервер — по кнопке или `Ctrl+S`; рядом `Discard`, возвращающий к сохранённому.

**Черновик кладётся поверх серверной раскладки поэлементно**, а не целиком: элемент, созданный после того, как черновик был сделан, получает позицию от сервера или от правила размещения, а всё, что двигал пользователь, остаётся там, куда он это поставил.

**Модельные изменения черновиком не становятся.** Команда валидируется по метамодели, атрибутируется и коммитится в момент, когда её сделали ([ADR-0004](adr/0004-commands-and-versioning.md)). Придержать её значило бы узнать уже на сохранении, что она была недопустима, — ровно противоположное тому, ради чего конвейер существует.

### 2.15. Не видно, что репозиторий шире представления

Счётчик «2 on view · 8 in repository» есть, но ощущения «есть ещё шесть элементов, которые можно показать» он не создаёт. Ключевая идея продукта — репозиторий больше любой диаграммы — держится на одной строке мелким шрифтом.

### 2.16. ✅ Исправлено: размер элемента был фиксированным

180×80 у всего, от бизнес-актора до системы с десятком модулей. Размер на диаграмме — это высказывание о значимости, и запрет его менять лишает архитектора выразительного средства, которое есть в любом рисовалке.

**Сделано:** рамка изменения размера у выделенного элемента, минимум больше у контейнера, чем у листа. Размер — это layout: он живёт в тех же колонках `width`/`height`, коммита не порождает ([ADR-0003](adr/0003-model-view-layout-separation.md)) и у каждого представления свой.

### 2.17. ✅ Исправлено: вложенность нельзя было показать на канвасе

`element.parent` в модели есть с фазы 2, а на канвасе система, её API и микросервисы лежали рядом одинаковыми прямоугольниками. Между тем вложенность — то, как ArchiMate рисует композицию, и главный способ показать границу системы.

**Сделано:** элемент, бро́шенный на другой, становится вложенным. Жест делает две вещи сразу, и они намеренно расходятся: `move-element` идёт командой и порождает коммит, координаты — нет. Контейнер рисуется рамкой в цвете своего слоя (серая рамка сказала бы, что система не относится ни к какому слою) и растягивается, чтобы ребёнок оказался внутри, а не поперёк границы. Вложить элемент в собственного потомка нельзя, из нескольких контейнеров под курсором выбирается меньший.

### 2.18. ✅ Исправлено: связь выходила только из двух точек

Точки были слева и справа. Линия к элементу сверху шла вбок и возвращалась, диаграмма читалась хуже, чем нарисованная от руки.

**Сделано:** точка на каждой стороне, все четыре и начинают, и принимают связь (`ConnectionMode.Loose`), видны при наведении и у выделенного. Линия уходит с той стороны, которая смотрит на цель.

### 2.19. ✅ Исправлено: новый элемент ложился поверх контейнера

Свободное место искалось в предположении, что все узлы 180×80. После появления контейнеров и изменяемого размера новый элемент накрывал контейнер — и его точки связи, так что связать его было уже нечем. Поиск свободного места теперь считает настоящие размеры.

## 4. Чего в UI намеренно нет

| Отсутствует | Почему |
|---|---|
| Кнопка «сохранить» | Изменение модели — команда, применяется сразу; layout сохраняется сам |
| Прямое редактирование связи на канвасе | Изменение связи — команда, проходящая валидацию; инлайн-правка обошла бы её |
| Выбор модели | Репозиторий один на workspace ([ADR-0008](adr/0008-one-graph-per-workspace.md)) |
| Тип C4 у элемента | Уровень C4 — глубина относительно фокуса, а не свойство ([ADR-0007](adr/0007-c4-projection.md)) |
| Совместное редактирование | Фаза 9; сейчас расхождение версий даёт 409 с обоими id коммитов |
